## Approach
The project is a Laravel 13 / Livewire application whose build pipeline combines Composer (PHP), npm/Vite (assets), and Docker. Everything is generated by **EnvKit Packer** — the Dockerfile and docker-compose.yml carry that attribution in their comments. There are no Makefiles; orchestration lives in `composer.json` scripts, `package.json`, `Dockerfile`, and one GitHub Actions workflow.

## Key Files
- `Dockerfile` — multi-stage image: `composer:2` for vendor install, `node:22-alpine` for asset build, `php:8.4-fpm-alpine` as runtime with nginx + php-fpm under supervisord.
- `docker/entrypoint.sh` — pre-flight: optional SQLite DB touch, retrying `php artisan migrate --force` up to 20 attempts (~40s), ownership fix, then exec supervisord.
- `docker/supervisord.conf` — four programs: `php-fpm`, `nginx`, `queue` (`artisan queue:work --sleep=3 --tries=3 --max-time=3600`), `scheduler` (`artisan schedule:work`). Each program's autostart is gated by env vars `RUN_WEB`, `RUN_QUEUE`, `RUN_SCHEDULER`, `RUN_REVERB`.
- `docker-compose.yml` — local compose stack: single `app` service built from `.` plus a `mysql:8.4` dependency. App container exposes port 8080.
- `composer.json` — defines `setup`, `dev`, `lint`, `test`, `ci:check` scripts; registers a local path repository for `packages/ContentBlocks` via symlink.
- `package.json` — Vite-driven frontend (`vite build` / `vite dev`); dependencies include Tailwind CSS v4, Alpine.js, CKEditor 5, Bootstrap 4, Laravel Vite plugin.
- `vite.config.js` — declares six entry points grouped into public site, auth, and admin bundles; ignores compiled Blade views during watch.
- `.github/workflows/lint.yml` — GitHub Actions job running on push/PR against `develop`, `main`, `master`, `workos`; PHP 8.4, installs both Composer and npm deps, runs `composer lint` (Pint).

## Architecture and Conventions
- **Multi-stage Docker build**: Vendor dependencies are installed first without dev packages (`--no-dev --no-scripts --no-autoloader --ignore-platform-reqs`), then assets are built in a separate Node stage, and only the resulting `public/build` directory is copied into the final runtime image. This keeps the production image small and excludes source tooling.
- **Supervisord as process supervisor**: A single container runs web (nginx/php-fpm), background queue worker, and scheduler concurrently. The entrypoint can disable any subset via environment variables (`RUN_WEB=false`, etc.), enabling flexible deployment profiles (e.g. worker-only pods).
- **Migration retry on startup**: `entrypoint.sh` retries `php artisan migrate --force` in a loop of up to 20 iterations with 2-second sleeps, tolerating the database container still booting. If migrations fail after the budget, it logs "migrations skipped" and proceeds.
- **Composer scripts as the CLI surface**: All development and CI tasks are invoked through `composer run <script>`:
  - `setup`: install deps, copy `.env.example`, generate key, migrate, npm install + build.
  - `dev`: concurrently runs `php artisan serve`, `queue:listen`, `pail`, and `npm run dev` using `concurrently`.
  - `test`: clears config, runs Pint check, then `php artisan test`.
  - `ci:check`: alias around `test`.
- **Local package development**: `packages/ContentBlocks` is registered as a `path` repository with `symlink: true`, so changes to the package source are reflected at runtime without re-publishing.
- **Frontend build targets**: Vite compiles six input files into separate bundles (site CSS/JS, auth CSS/JS, admin CSS/JS). The build output lands in `public/build` and is consumed by the Docker image.
- **CI quality gate**: The GitHub Action checks out code, sets up PHP 8.4, configures Flux credentials from secrets, installs both Composer and npm dependencies, then runs `composer lint`. Auto-commit of style fixes is commented out in the workflow.

## Rules and Constraints
- **PHP version**: The Dockerfile pins `php:8.4-fpm-alpine` and the workflow uses `shivammathur/setup-php@v2` with `php-version: '8.4'`; `composer.json` requires `php ^8.2`.
- **Runtime ports**: The image exposes `8080` (nginx listens on this port per `docker/nginx.conf`); the compose file maps `${APP_PORT:-8080}:8080`.
- **Database default**: Compose defaults to `DB_CONNECTION=mysql` pointing at a sibling `db` service; `entrypoint.sh` additionally supports `sqlite` when `DB_CONNECTION=sqlite` (creates `database/database.sqlite`).
- **Asset bundling**: Production builds require `npm ci` followed by `npm run build`; the Dockerfile copies `pnpm-lock.yaml* yarn.lock* bun.lock*` but only `package*.json` is staged before `npm ci`, so lock resolution depends on whichever lock file exists alongside `package.json`.
- **Service toggles**: Enabling/disabling processes is controlled exclusively through `RUN_WEB`, `RUN_QUEUE`, `RUN_SCHEDULER`, and `RUN_REVERB` environment variables consumed by supervisord configuration.
- **Migrations**: Run automatically on container start unless `RUN_MIGRATIONS=false`; failures beyond the retry budget do not abort the container — they log and continue.
- **Code style enforcement**: `composer.json` registers Pint via `lint` and `lint:check` scripts; the CI workflow runs `composer lint` (equivalent to `pint --parallel`) and fails the job on violations.
