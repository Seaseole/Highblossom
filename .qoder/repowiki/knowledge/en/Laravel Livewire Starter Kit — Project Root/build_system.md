## Approach

The project is a Laravel 13 + Livewire application whose build pipeline has three layers:

1. **PHP dependency management** — Composer (`composer.json`), with PSR-4 autoloading for `App\`, `Database\Factories\`, `Database\Seeders\`, and a local path repository for the in-repo `packages/ContentBlocks` package.
2. **Frontend asset pipeline** — Vite 8 via `laravel-vite-plugin`, producing assets into `public/build`. Entrypoints are split per UI surface: public site (Tailwind v4), auth layout, and the AdminLTE-based admin panel.
3. **Containerized runtime** — A multi-stage Dockerfile builds vendor assets and frontend assets separately, then ships a single PHP 8.4 Alpine image running nginx + php-fpm + queue worker + scheduler under supervisord, orchestrated by `docker-compose.yml`.

No Makefile exists; orchestration is delegated to Composer scripts, npm scripts, and Docker Compose.

## Key Files

- `composer.json` — PHP dependencies, autoload map, Composer scripts (`setup`, `dev`, `lint`, `test`, `ci:check`).
- `package.json` — Vite/npm entrypoints (`build`, `dev`) and frontend dependencies.
- `vite.config.js` — Vite plugin config declaring all input files for site/auth/admin bundles.
- `Dockerfile` — Multi-stage build: `composer:2` → vendor install, `node:22-alpine` → asset build, `php:8.4-fpm-alpine` → runtime image.
- `docker-compose.yml` — Local dev stack: `app` service (built from `.`) depends on `db` (MySQL 8.4).
- `docker/entrypoint.sh` — Prepares SQLite DB if needed, retries migrations against a still-starting database, then execs supervisord.
- `docker/supervisord.conf` — Four managed programs: `php-fpm`, `nginx`, `queue` (`artisan queue:work --tries=3 --max-time=3600`), `scheduler` (`artisan schedule:work`).
- `.github/workflows/lint.yml` — GitHub Actions job running Pint against PHP 8.4 on push/PR to `develop`, `main`, `master`, `workos`.
- `pint.json` — Laravel Pint configuration file (style rules).

## Architecture and Conventions

### Multi-stage Docker image

The Dockerfile is generated by EnvKit Packer and follows a strict three-stage pattern:

1. **Vendor stage** (`FROM composer:2 AS vendor`): copies only `composer.json`/`composer.lock*`, runs `composer install --no-dev --no-scripts --no-autoloader --prefer-dist --ignore-platform-reqs`, then copies the rest and dumps an optimized autoloader.
2. **Assets stage** (`FROM node:22-alpine AS assets`): copies `package*.json` plus any lockfile variants (`pnpm-lock.yaml*`, `yarn.lock*`, `bun.lock*`), runs `npm ci`, then `npm run build`.
3. **Runtime stage** (`FROM php:8.4-fpm-alpine`): installs nginx, supervisor, and PHP extensions (`pdo_mysql`, `pdo_pgsql`, `mysqli`, `bcmath`, `gd`, `intl`, `zip`, `opcache`, `pcntl`, `exif`) via the `mlocati/docker-php-extension-installer`; copies built vendor dir and `public/build`; sets ownership of `storage`, `bootstrap/cache`, `database` to `www-data`; exposes port 8080.

All processes share one container process tree managed by supervisord, controlled at runtime through environment variables `RUN_WEB`, `RUN_QUEUE`, `RUN_SCHEDULER`, `RUN_REVERB`.

### Entrypoint and migration strategy

`docker/entrypoint.sh` performs two pre-start tasks before handing off to supervisord:

- Creates `database/database.sqlite` when `DB_CONNECTION=sqlite`.
- Retries `php artisan migrate --force --no-interaction` up to 20 times with a 2-second backoff (≈40 seconds total) so that the app can start even while the MySQL container is initializing. Migration failures are logged but do not abort startup.

Afterwards it chowns `storage bootstrap/cache database` to `www-data` and `exec`s supervisord.

### Supervisor program conventions

Every long-running process in `docker/supervisord.conf` shares a common shape:

- `autorestart=true`, `stopasgroup=true`, `killasgroup=true`.
- Stdout/stderr go to `/dev/stdout` and `/dev/stderr` (for container logging).
- The `queue` program runs as `www-data` with `--sleep=3 --tries=3 --max-time=3600`.
- Each program's `autostart` is gated by its matching `%ENV_RUN_*%` variable.

### Composer script contract

The `scripts` section defines the project's command surface:

| Script | Meaning |
|---|---|
| `setup` | Install deps, copy `.env.example` → `.env`, generate key, run migrations, install npm, build assets |
| `dev` | Runs four concurrent processes: `php artisan serve`, `php artisan queue:listen --tries=1 --timeout=0`, `php artisan pail --timeout=0`, `npm run dev` |
| `lint` / `lint:check` | Run Pint in parallel (with `--test` mode for CI) |
| `test` | Clear config → lint check → `php artisan test` |
| `ci:check` | Alias over `@test` with process timeout disabled |
| `post-autoload-dump` | Discover packages after autoload dump |
| `post-update-cmd` | Publish Laravel assets |
| `post-root-package-install` | Copy `.env.example` |
| `post-create-project-cmd` | Generate key, create sqlite DB, run migrations gracefully |

Composer config enforces `optimize-autoloader`, `preferred-install: dist`, `sort-packages`, and `minimum-stability: stable` with `prefer-stable: true`.

### Frontend asset convention

`vite.config.js` declares explicit input files grouped by UI layer:

- Public site: `resources/css/app.css`, `resources/js/app.js`, `resources/js/site-booking.js`, `resources/js/site-alpine.js` (Tailwind v4).
- Auth layout: `resources/css/auth.css`, `resources/js/auth-alpine.js`.
- Admin panel: `resources/css/admin.css`, `resources/js/admin.js` (Bootstrap 5 + AdminLTE 4).

Vite refresh is enabled and `storage/framework/views/**` is explicitly ignored from watching.

### Local development stack

`docker-compose.yml` defines two services:

- `app`: builds from `.`; maps `${APP_PORT:-8080}:8080`; runs with `APP_ENV=production`, `APP_DEBUG=false`, `LOG_CHANNEL=stderr`; connects to `db` on `mysql:3306`.
- `db`: `mysql:8.4` with persistent volume `db-data:/var/lib/mysql`.

The comment above `docker-compose.yml` documents the expected invocation: `docker compose up --build`.

### CI pipeline

`.github/workflows/lint.yml` runs a single `quality` job on `ubuntu-latest` with PHP 8.4:

1. Checks out code.
2. Adds Flux credentials via `composer config http-basic.composer.fluxui.dev` using secrets `FLUX_USERNAME` and `FLUX_LICENSE_KEY`.
3. Installs dependencies (`composer install --no-scripts` + `npm install`).
4. Runs `composer lint` (Pint).

It triggers on push and pull_request to `develop`, `main`, `master`, and `workos`.

## Conventions and Constraints

- **Runtime image**: PHP 8.4 Alpine with nginx + php-fpm + supervisord; no separate web/server containers — everything runs in one process tree.
- **Port**: The container exposes port 8080 (not 80); `docker-compose.yml` maps host port via `$APP_PORT` defaulting to 8080.
- **Supervisor-gated processes**: Running any of web, queue, or scheduler is opt-in via `RUN_WEB`, `RUN_QUEUE`, `RUN_SCHEDULER`, `RUN_REVERB` environment variables.
- **Migration resilience**: The entrypoint retries migrations up to 20 times against an unavailable database rather than failing fast.
- **Dependency resolution order**: Vendor installation happens before copying source code in the Dockerfile to maximize cache hits.
- **Asset build isolation**: Frontend assets are built in a dedicated `node:22-alpine` stage and copied into `public/build` of the final image.
- **CI runs Pint only**: The workflow does not execute tests; `composer ci:check` is defined but not invoked by the workflow.
- **Local dev uses `docker compose up --build`** as documented in the docker-compose header.
- **Internal package publishing**: `packages/ContentBlocks` is registered as a `path` repository with symlink option in `composer.json`, enabling development-time linking without publishing.
